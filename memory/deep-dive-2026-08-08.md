## Architecture review 2026-08-08 (agent) — key findings
Verdict: the write-side architecture (spine → signals → score → funnel enrichment; watermarks; differential
upserts) is sound. The read side violates "ingest broad, surface narrow": three read paths grow unbounded
against Convex's hard caps (~16,384 docs / 8 MiB per query).

- **A25-1 CRITICAL — `/monitor` keeper queries unbounded.** `keepersToEmail` + `listKeepers`
  (`monitorData.ts:329-356`) collect ALL keeper rows ever (fattest rows, 6-12 KB each; keepers never
  retire). Hard page failure + silent digest death in ~3-6 months. FIX: nightly retire pass (keeper +
  stale `lastSeen` → archived), `["keeper","emailedAt"]` + `["keeper","dealScore"]` indexes + `take(N)`.
- **A25-2 CRITICAL — `/leads` `deriveLeads` on a countdown** (A-C1 sharpened): in-window signalEvents +
  full leadStatus + full parcelEquity collects → exceeds the 16k-doc cap ~mid-2027 → flagship page THROWS.
  FIX: materialized `leadScores` table (one bounded row per parcel-with-signals) updated at write time;
  `/leads` reads indexed top-N; move `payload` to a side table.
- **A25-3 CRITICAL (reliability) — worst-case `analyzeOne` exceeds the 10-min action limit** (4×150s
  fetches + gaps ≈ 11.5 min): killed action → row stuck `pending`, no error; run marked "complete" BEFORE
  fan-out so the 20h cron guard skips the safety net; `analyzedCount/keeperCount/emailedCount` on
  monitorRuns are dead (always 0). A fully-blocked night looks green. FIX: cap retry budget inside
  analyzeOne, pending-sweeper + "0 analyzed" alert, real counters, completion-triggered digest.
- **A25-4 IMPORTANT — Firecrawl credit leaks** (~3-8k credits/mo on a 17.8k plan): per-zip comps cache is
  module-level → cold per scheduled action → same zip's Redfin re-scraped per listing (fix: `zipComps`
  table, 24h TTL); legal cron runs the LLM extraction BEFORE its idempotency check (pure reorder);
  webhook discards Firecrawl's own page-1 content and re-scrapes it (forward `content`); Zillow scrapes
  request markdown+rawHtml but only rawHtml is parsed (drop markdown); sheriff weekday cron scrapes the
  monthly PDF ~22×/mo to learn "already scraped".
- **A25-5 IMPORTANT — digest under-reports its night**: fires at `scheduled×3s + 90s` while each
  analyzeOne takes 1-10+ min → late keepers slide 24h. FIX: completion-triggered digest (pendingCount).
- **A25-6 IMPORTANT — spine steady-state** (A-H1/A-H2 still open): weekly CDC reads ~203k FULL docs
  (~0.7 GB/mo) to diff 8 MB of keys (fix: `parcelKeys` side table); NO attribute-refresh cron — owner
  names are frozen at the 2026-06-11 seed → absentee + foreclosure-matcher precision rots (fix: monthly
  `seedSpine` cron — differential upsert makes it cheap); no watchdog for killed self-rescheduling chains.
- **A25-7 IMPORTANT — no retention anywhere**: scrapeEvents (never deleted), scrapeRuns, monitorRuns,
  errorLogs (sendDigest logs a config "error" DAILY if RESEND key unset), parcelSync. One weekly
  retention cron fixes all.
- **A25-8 IMPORTANT — signal precision debts** (A-M2/M3/M4 open): 30-day cold-start never captured
  in-flight foreclosures (one-time 365d re-sweep); auto-attach leaves the unmatched `fc:<caseId>` ghost
  row (double count + noisy review queue); statuses fossilize (monthly re-pull of open cases).
- Minors: price INCREASES never update listPrice; keepers never re-analyzed on age; dashboardStats +
  geocode listMissing collect whole tables; signalStatsInternal will throw past 16k events.
- Sustainability: bounded-projection policy; durable fan-out (Convex Workpool) replacing open-loop
  `runAfter(i×stagger)`; market/county as config not code (NCC hardcoded in ~7 modules, `prclid`
  un-namespaced); per-source credit metering; foreclosure-stem recall unmeasured (diff swept cases vs
  `SheriffSales/0` ArcGIS layer to detect missed lender stems).
- Top-5 by impact/effort: (1) bound keeper set + indexes (½ day) · (2) materialize leadScores (2-4 d) ·
  (3) truthful self-terminating monitor fan-out (1-2 d) · (4) credit-leak batch (~1 d, saves 30-60% of
  Firecrawl spend) · (5) spine freshness + watchdog + 365d re-sweep (1-2 d).

## Security audit 2026-08-08 (agent) — key findings
Headline: **no Critical**. All prior fixes verified still intact (token-lookup bypass guard, HMAC
raw-bytes + timing-safe compare, webhook instant-ACK, CSV formula injection FIXED in `mailCsv.ts:31`,
digest esc() coverage, 256-bit portal tokens, requireUser coverage on all ~90 public fns, no secrets in
the client bundle, storage ACLs clean).
- **S25-1 IMPORTANT — email-fallback account linking trusts unverified `identity.email`**
  (`getAuthUser.ts:20-27`, `users.ts:37-48`): byEmail fallback + permanent rebind with NO
  `email_verified` check → admin takeover IF Clerk config ever permits unverified email claims.
  FIX: require `identity.emailVerified === true` before the email-fallback link (add the claim to the
  Clerk JWT template); prefer linking invites by invitation ticket; confirm Clerk verification-required.
- **S25-2 IMPORTANT — one Google key both client-bundled AND server-side** → necessarily
  referrer-unrestricted → harvestable from the public JS bundle for billing abuse. FIX: split into a
  referrer-restricted browser key + a server-only key (Geocoding + Street View Static), quota caps.
  (Supersedes the 2026-06-02 "one key serves both" convenience lesson — it works, but it's the vuln.)
- S25-3 Minor — scraped Zillow URLs rendered as raw `href` in `MonitorPage.tsx:578`,
  `PropertyDetail.tsx:282`, `PropertyMap.tsx:160` (javascript: sink; `pages.tsx:141` has the correct

- S25-4 Minor — webhook has no replay protection (10-min dup guard caps abuse; optional timestamp check).
- S25-5 Minor — `devScrapeSheriff/Legal/devMonitorScan` are public actions gated only by IRES_DEV env
